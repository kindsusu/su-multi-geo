# 의도 발굴 — 어떤 질문으로 페이지를 만들 것인가

의도 랜딩의 성패는 글솜씨가 아니라 **질문 선택**에서 갈린다. 아무도 치지 않는 질문은
완벽하게 답해도 노출이 0이고, 원출처가 확고한 질문은 잘 써도 인용을 뺏긴다.
순서는 **발굴 → 선별 → 매핑 → 우선순위**이며, 발굴 단계에서 지어내지 않는 것이 핵심이다.

## 1. 발굴 소스 — 상상하지 말고 캐라

- [ ] **GSC 검색어 보고서** (1순위). 이미 노출은 되는데 **전용 랜딩이 없는 상위 검색어 =
      다음에 만들 페이지**다. 노출은 있고 클릭이 낮은 검색어는 수요가 이미 증명된 것이다
- [ ] **네이버 서치어드바이저 검색어**. 한국 시장이면 GSC와 목록이 상당히 다르다 —
      구어체·지역명·"얼마" 류 질문이 여기서 나온다
- [ ] **자동완성·연관검색어** (구글·네이버). 검색창에 핵심어를 치고 뜨는 목록을 그대로
      적어라. 실제 질의 로그에서 나온 문자열이라 창작보다 정확하다
- [ ] **각 AI 엔진에 실제로 질문을 던져 경쟁 인용 페이지 역추적**. ChatGPT·Gemini·
      Claude·Perplexity에 대상 질문을 치고 **출처 목록에 뜨는 페이지들을 열어** 어떤 질문에
      어떤 형태로 답했는지 본다. 지금 인용을 가져가는 페이지가 곧 경쟁 기준선이다
- [ ] **상담·CS 문의 기록**. 현장에서 실제로 받은 질문은 검색 도구에 안 잡히는 롱테일의
      원천이고, 문장이 이미 사용자 언어로 되어 있다. 상담 로그·문의 게시판·콜 메모를 훑어
      반복 질문 상위 20개를 뽑아라

⚠️ 키워드 도구의 추정 검색량만으로 목록을 만들지 마라. 추정치는 브랜드·업종어에서
크게 틀린다. **우리 GSC에 실제로 찍힌 노출**이 항상 더 강한 근거다.

## 2. 선별 기준 — 답할 수 있는 질문만 남긴다

- [ ] **데이터로 확정 답할 수 있는가.** "요금이 얼마인가", "며칠 걸리나"는 답이 하나다.
      "어디가 좋을까", "지금 사야 하나"는 예측·권유형이라 제외한다 — 규제 업종에서는
      위험 요소이기도 하고, 답변엔진도 확정 문장을 우선 추출한다
- [ ] **우리가 1차 소스가 될 수 있는가.** 우리가 직접 산출·집계·관측하는 숫자로 답하는
      질문을 최우선에 둔다. 남의 통계를 요약해 답하는 질문은 원출처에게 인용을 뺏긴다
      (→ `geo.md` 3번)
- [ ] **기준일을 붙일 수 있는가.** 기준 없는 답은 낡으면 조용히 틀린 페이지가 된다.
      갱신 주체가 없는 질문은 만들지 마라
- [ ] 답이 한 문장으로 안 나오면 질문이 너무 크다. 쪼개거나 버려라

## 3. 질문 → 페이지 매핑 규칙

- [ ] **질문 하나 = 페이지 하나.** 한 페이지에서 열 가지를 다루면 어느 질문의 답으로도
      추출되지 않는다
- [ ] URL·h1·title이 **질문을 그대로** 반영한다 (URL은 질문의 핵심 명사구)
- [ ] **첫 문단에서 40자 내외 직답.** 서론·회사 소개를 앞에 두지 마라
- [ ] 직답 아래에 **근거 데이터 표** — 항목·수치·단위·기준일. 표는 엔진이 가장 안정적으로
      파싱하는 형태다
- [ ] 관련 질문은 하단 FAQ 3~5개로 붙이고, 각각이 독립 페이지가 될 만큼 커지면 그때 분리한다

### 포맷 — 페이지 수보다 잘 구조화된 한 편

- [ ] **비교·총정리형 가이드 한 편에 자원을 몰아라.** 잘 만든 단일 페이지 하나가
      도메인 전체 인용의 상당 지분을 가져가고 수백 개 키워드를 혼자 커버하는 패턴이
      실측에서 반복 관측된다. 얇은 페이지 30개보다 조건·기준이 다 들어간 한 편이 낫다
- [ ] **감성 소구가 아니라 검토용 콘텐츠로 써라.** 인용되는 페이지의 공통점은
      **선택 기준의 구조화**다 — 가격·스펙·조건·장단점을 표로 나란히 놓은 형태.
      "우리와 함께라면" 류 카피는 인용 대상이 아니다
- [ ] **커뮤니티 Q&A형 콘텐츠가 검토 단계 의도를 크게 흡수한다.** "○○ 써보신 분",
      "A랑 B 중에" 류 질문의 답이 커뮤니티에 있으면 인용도 거기로 간다.
      자사 Q&A(FAQ·문의 아카이브)를 그 형태로 설계하는 것도 GEO 과제다
- [ ] ⚠️ **PDF로만 배포한 보고서는 웹에 반영되지 않는다.** 내용이 아무리 좋아도 AI가 못
      가져간다 — 같은 내용을 웹 페이지로 병행 발행하고 PDF는 첨부로 둬라
- [ ] **보고서·통계 페이지에 조사 방법이 없으면 근거로 채택되지 않는다.** 표본·기간·산출식을
      본문에 적어라

## 4. ⚠️ 카니발라이제이션 함정

비슷한 질문을 각각 페이지로 쪼개면 **서로를 잠식한다.** "제주 렌터카 요금"과
"제주 렌터카 가격"은 검색어가 다를 뿐 답이 같다 — 두 페이지를 만들면 검색엔진은 어느
쪽을 올릴지 정하지 못하고 둘 다 내린다.

판단 기준은 검색어 문자열이 아니라 **답의 내용**이다.

- 답이 같다 → **한 페이지.** 표현 변형은 본문·FAQ에서 흡수하고 canonical로 정본을 고정
- 답이 다르다(다른 표·다른 기준·다른 대상) → 별도 페이지
- 이미 쪼개 놓았다면 병합 후 301 — 약한 페이지 둘보다 강한 페이지 하나가 항상 낫다

## 5. 우선순위 매기기

세 축을 곱해서 줄을 세운다. 하나라도 0에 가까우면 뒤로 민다.

| 축 | 근거 | 낮음(1) ↔ 높음(3) |
|---|---|---|
| 검색량 근거 | GSC·서치어드바이저 실측 노출 | 추정치만 있음 ↔ 실측 노출 다수 |
| 1차 소스 가능성 | 우리 데이터로 답하는가 | 남의 통계 요약 ↔ 우리만 가진 숫자 |
| 제작 비용(역산) | 데이터·표를 만들 수 있는가 | 신규 집계 필요 ↔ 기존 데이터 재사용 |

- 첫 배치는 **6~10개**로 끊어라. 30개를 동시에 만들면 어느 것이 효과를 냈는지 못 잰다
- 배치를 내보낸 날짜를 기록하고 14일 뒤 재측정한다 (→ `measure.md`)
- 재측정 때 GSC 검색어 보고서를 다시 훑으면 **다음 배치 목록이 자동으로 나온다.**
  이 루프가 돌기 시작하면 질문 발굴은 더 이상 추측이 아니다
