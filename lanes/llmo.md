# LLMO — 모델이 기억하게 만들기

GEO의 상대가 웹을 뒤지는 AI라면, LLMO의 상대는 **모델이 이미 들고 있는 지식**이다.
검색을 한 번도 거치지 않고 "○○ 비슷한 서비스 뭐 있어?"라고 물었을 때 이름이 나오느냐 —
이 레인이 다루는 건 그 하나다.

변화 시점은 모델·학습 데이터·제품 업데이트에 따라 달라 예측할 수 없다. 검색을 끈 동일 조건의
답변을 분기마다 기록하되, 응답 변화가 특정 게시나 크롤 정책의 효과라고 단정하지 않는다.

## 1. 이름을 한 가지로 못 박는다

- [ ] 서비스명은 **모든 표면에서 같은 표기로** 통일한다. 한/영 병기 여부, 띄어쓰기 한 칸까지
      포함이다. 표기가 두세 갈래로 갈리면 모델은 그것들을 서로 다른 실체로 학습한다
- [ ] Organization JSON-LD의 `sameAs` 배열에 공식 계정·문서를 빠짐없이 나열한다. 위키 문서,
      앱스토어 페이지, GitHub, SNS, 유튜브 채널 — 흩어진 표면을 하나로 묶는 선언이다
- [ ] `@id`를 전역 1회 선언하고 참조하라 (`seo.md` 5번). 페이지마다 새로 선언하면
      엔티티가 쪼개진다
- [ ] 이름 충돌 점검: 같은 이름의 다른 서비스가 검색에 잡히면 모델도 섞는다

## 2. 학습 데이터까지 살아남는 자리

학습은 웹을 고르게 훑지 않는다. **크롤링 가치가 높다고 판단된 표면**에 집중된다. 거기에 정확한
서술을 남겨라.

- [ ] 위키류 문서: 홍보체가 아니라 **사실 서술체**로 — 과장·수식어가 많으면 편집 반려되고
      모델도 광고로 학습한다
- [ ] GitHub 공개 저장소 README는 강한 학습 표면이다
- [ ] 개발자 커뮤니티·기술 블로그: 어떻게 만들었는지 남긴 기록이 그대로 브랜드 설명문이 된다
- [ ] 뉴스·보도: 보도자료 하나가 수십 개 매체로 복제되면서 같은 문장이 코퍼스에 여러 번 박힌다
- [ ] 학습용 크롤러 정책을 사업 목적과 콘텐츠 권리에 맞게 정한다. 허용은 향후 학습·기억을
      보장하지 않고, 특정 봇 차단만으로 모든 모델의 기존 지식과 다른 데이터 경로가 사라지지 않는다

## 3. 흔들리지 않게 유지하기

- [ ] **퍼머링크 유지**: URL을 바꾸면 모델이 기억하는 주소가 404가 된다.
      바꿔야 하면 301을 **영구히** 유지
- [ ] 핵심 사실(가격·기능·정체성)이 바뀌면 **모든 표면을 같이 갱신** —
      갱신을 빠뜨린 표면 하나가 다음 학습에서 모델의 "사실"로 굳는다

## 4. 검증 (분기 1회)

주요 모델(ChatGPT·Claude·Gemini)에 **브라우징을 끄고** "○○가 뭐야?"를 묻는다.

| 결과 | 진단 | 조치 |
|---|---|---|
| 아예 모름 | 표면 부족 | 2번 표면 확대 |
| 틀리게 앎 | 낡거나 분열된 서술 | 1번 일관성 + 3번 갱신 |
| 맞게 앎 | 정상 | 유지 관리 |

답변 원문과 모델·버전·언어·지역·검색 비활성 상태를 기록해 분기마다 비교한다. 이는 해당 조건의
관측값이며 학습 반영이나 원인을 직접 증명하지 않는다.
